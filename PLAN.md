# План развития ScratchJr Web

Дата создания: 2026-08-04
Репозиторий: `AndreiPabiarzhyn/ScratchJr-Desktop`

## Цель

Переделать проект из Electron desktop-приложения в статический сайт без бэкенда:
вся логика ScratchJr работает в браузере, данные пользователя хранятся полностью
в браузере (IndexedDB), деплой — статический хостинг (например, GitHub Pages).
Решение принято 2026-08-04 взамен предыдущей десктоп-траектории (см. «Архив:
десктоп-этапы» ниже) — не в дополнение к ней.

## Правила работы

- После каждого заметного изменения обновлять этот файл.
- Не смешивать механическую гигиену, исправления поведения и портирование на веб
  в одном коммите.
- Перед изменениями в хранилище данных (IndexedDB/sql.js) делать резервную копию
  сценария и проверять восстановление.
- Для каждого завершённого милстоуна фиксировать критерий приёмки и его
  результат.
- Независимые проверки/аудиты выполнять параллельными субагентами (инструмент
  `Agent`), мутирующие и рискованные действия — только основным агентом после
  явного согласия пользователя.

## Архитектурное решение

- **Хранилище**: `sql.js` (обновить до современного WASM-билда `sql.js@1.x`)
  выполняется прямо в браузере; вся SQL-логика `src/app/src/iPad/IO.js`
  остаётся без изменений. Бинарный экспорт БД (`db.export()`) персистится в
  IndexedDB одним ключом (например, через `idb-keyval`). Медиафайлы (SVG/аудио/
  картинки) как и раньше хранятся внутри той же SQLite БД в таблице
  `PROJECTFILES` — отдельная IndexedDB-схема для медиа не нужна.
- **Единственный шов замены** — `src/app/src/iPad/iOS.js` (`tabletInterface`)
  сегодня указывает на `window.tablet = new ElectronDesktopInterface()`
  (`src/electronClient.js`). Порт — это в основном написание
  `WebTabletInterface` с тем же набором методов + добавление сборщика, а не
  переписывание `src/app/src/**` (редактор/рисовалка/лобби уже не зависят от
  Electron напрямую).
- **Сборка**: Vite в режиме multi-page app (4 входа: `index.html`, `home.html`,
  `editor.html`, `gettingstarted.html`) — сохраняет текущую модель обычной
  многостраничной навигации (`window.location.href = '...'`), без переписывания
  на SPA-роутер.
- **Экспорт/импорт `.sqlite`** — добавляется как резервная копия/перенос между
  устройствами (решение пользователя, т.к. без файловой системы IndexedDB —
  единственное хранилище).
- **Один активный набор проектов** — без поддержки нескольких БД-«наборов»
  (starter kits) на первом этапе (решение пользователя).
- **`analyticsEvent` убирается**, **parental gate остаётся** как есть (решение
  пользователя).

По пути найдены и исправлены 4 реальные ошибки инициализации в браузере (все
не имели отношения к БД напрямую, но блокировали запуск любой страницы):
- `global is not defined` — `vite.config.js`: добавлен `define: {global:
  'globalThis'}` (старые Node-ориентированные зависимости — jszip, sql.js,
  intl — ссылаются на Node-глобал `global`).
- `eve is not defined` — `snapsvg`'s `dist/snap.svg.js` присваивает
  необъявленной глобальной `eve` (работало в Electron только благодаря
  нестрогому CJS-враппер Node). Фикс: `globalThis.eve = undefined;` в самом
  начале `webClient.js` (первый импорт `appEntry.js`) — переприсваивание
  существующей глобали strict mode разрешает, в отличие от объявления новой.
- `require is not defined` — `src/app/src/utils/Localization.js` использовал
  рантайм `require(...)` (старый Babel/electron-compile паттерн) для загрузки
  locale-data файлов `intl`/`intl-messageformat`. Заменено на статические
  `import '...'`.
- `IntlMessageFormat is not defined` — после замены `require` на `import`,
  `intl-messageformat/dist/locale-data/*` (которым нужен уже готовый глобал
  `IntlMessageFormat`) стали грузиться ДО присвоения `global.IntlMessageFormat
  = ...` (ES-импорты хоистятся и резолвятся в порядке следования, в отличие
  от `require()`, который выполнялся строго по порядку строк). Исправлено
  вынесением в отдельный модуль `utils/intlMessageFormatGlobal.js`,
  импортируемый первым, до locale-data импортов.
- Дополнительно: `Uncaught InvalidCharacterError` в `btoa` — сид-проект
  ссылался на миниатюру как `"samples/Bump.png"` (путь для галереи сэмплов),
  а код «Моих проектов» (`Home.js`→`IO.getAsset`) ждёт обычный MD5-ключ из
  `PROJECTFILES`; поправлено в `webDb.js` (префикс `samples/` убран из сида).
- `src/app/css/` перенесён в `src/app/public/css/` — эти файлы на самом деле
  шаблоны с `${...}` JS-выражениями (вычисляются рантайм-препроцессором
  приложения, не настоящий CSS), а Vite пытался парсить их через PostCSS при
  любом прямом запросе `.css`, даже вне графа модулей. `publicDir` отдаёт их
  как есть, без какой-либо обработки.
